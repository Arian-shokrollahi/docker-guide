# read_only
---
ا-`read_only` یک **Service-level key** است که فایل‌سیستم اصلی کانتینر را فقط‌خواندنی می‌کند.

مثلاً:

```
services:
  app:
    image: my-app
    read_only: true
```

یعنی داخل کانتینر، برنامه نمی‌تواند روی filesystem اصلی فایل جدید بسازد یا فایل‌ها را تغییر بدهد.

فلسفه‌اش بیشتر **امنیت** است؛ اگر برنامه یا مهاجم داخل کانتینر بخواهد فایل‌های سیستم را تغییر بدهد، محدود می‌شود.

اگر برنامه واقعاً نیاز به نوشتن داشته باشد، باید مسیرهای لازم را جداگانه writable کنی، مثلاً با `volume` یا `tmpfs`:

```
services:
  app:
    image: my-app
    read_only: true

    volumes:
      - app-data:/app/data

    tmpfs:
      - /tmp

volumes:
  app-data:
```

اینجا:

- کل filesystem کانتینر → read-only
- ا-`/app/data` → قابل نوشتن چون Volume است
- ا-`/tmp` → قابل نوشتن چون tmpfs است

پس برای جزوه:

ا-**`read_only: true` فایل‌سیستم اصلی کانتینر را فقط‌خواندنی می‌کند و برای افزایش امنیت استفاده می‌شود؛ مسیرهایی که نیاز به write دارند باید جداگانه با Volume یا tmpfs فراهم شوند.**
