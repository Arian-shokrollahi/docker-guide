# رابطه بین ports در داکر کامپوس و EXPOSE در داکر فایل چیست:
---
#### اول EXPOSE چیه
ا-`EXPOSE` مشخص می‌کنه که این image **انتظار داره برنامه داخل container روی چه پورتی گوش بده**.

مثلاً:

```
EXPOSE 5000
```

یعنی:

> این برنامه داخل کانتینر معمولاً روی پورت `5000` سرویس می‌ده.

اما خود `EXPOSE` باعث نمی‌شه برنامه واقعاً روی اون پورت listen کنه. این خود برنامه‌ست که باید مثلاً روی `5000` اجرا بشه.

پس:

```
EXPOSE 5000
```

یعنی:  
`container-side intended port = 5000`

و اگر بخوای از Host بهش وصل بشی:

```
ports:
  - "8000:5000"
```

یعنی:

```
Host 8000  →  Container 5000
```

---

### حالا بریم سراغه رابطه بین EXPOSE و ports
اگر داخل Dockerfile داشته باشی:

```
EXPOSE 5000
```

و برنامه هم واقعاً داخل کانتینر روی پورت `5000` گوش بده، در Compose سمت راست باید همون پورت کانتینر باشه:

```
services:
  backend:
    ports:
      - "8000:5000"
```

یعنی:

```
8000 = Host
5000 = Container
```

پس:

```
EXPOSE 5000
        ↓
ports:
  - "8000:5000"
           ↑
     معمولاً همین پورت
```

ولی نکته مهم اینه که `EXPOSE` خودش پورت برنامه رو تغییر نمی‌ده. چیزی که واقعاً مهمه اینه که برنامه داخل کانتینر روی چه پورتی `listen` می‌کنه.

مثلاً اگر Dockerfile اشتباهی اینو داشته باشه:

```
EXPOSE 5000
```

ولی برنامه واقعاً روی `3000` اجرا بشه، باید بنویسی:

```
ports:
  - "8000:3000"
```

نه `8000:5000`.

پس قانون دقیق‌تر اینه:

> سمت راست `ports` باید پورت واقعی سرویس داخل کانتینر باشه؛ `EXPOSE` معمولاً فقط همون پورت رو مستند می‌کنه.
