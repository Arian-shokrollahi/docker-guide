# کلید بعدی کلید configs
---

از `configs` وقتی استفاده می‌کنیم که یک **فایل تنظیمات غیرحساس** داریم و می‌خواهیم آن را به شکل مرتب و مشخص در اختیار یک یا چند سرویس قرار بدهیم.

مثلاً فایل‌هایی مثل:

- `nginx.conf`
- `app.conf`
- `settings.yaml`
- `redis.conf`

اگر بخوای برای جزوه یک جمله بنویسی:

ا-**`configs` زمانی استفاده می‌شود که بخواهیم فایل‌های تنظیمات غیرحساس را از بیرون کانتینر مدیریت کنیم و داخل سرویس‌ها قرار بدهیم.**

یعنی به‌جای اینکه فایل config را داخل Image بچسبانی، می‌توانی آن را جدا نگه داری و Compose آن را به سرویس بدهد.

---
## ما در کجاها ازش استفاده میکنیم
- ما در دو قسمت ازش استفاده میکنیم
- ۱-top level
- ۲-service-level
----
## ساختار به چه صورته
- ۱-در سطح سرویس به این صورت است که سما میاید یه اسم مستعار تگ برایه اون فایلی که میخواید در کانفیگ باشه میزارید یعنی به این صورت است که شما در مبدا میاید اون نامه مستعار رو میزارید و در سطح بالا top level  برایه اون اسمه مستعار یه مسیر کامل انتخاب میکنید
```
Top-level:
اسم config → مسیر فایل روی Host

Service-level:
source → اسم همان config
target → مسیر داخل Container
```
در Top-level `configs` یک **اسم یا شناسه‌ی دلخواه** برای فایل config می‌سازی و بعد مسیر فایل واقعی را به آن وصل می‌کنی.

مثلاً:

```
configs:
  nginx-config:
    file: ./nginx.conf
```

اینجا:

- `nginx-config` → اسم/شناسه‌ای که خودت انتخاب کردی
- `./nginx.conf` → مسیر فایل واقعی روی سیستم

بعد داخل سرویس با همان اسم صداش می‌زنی:

```
services:
  nginx:
    configs:
      - source: nginx-config
        target: /etc/nginx/nginx.conf
```

پس ذهنی این‌طوری حفظش کن:

**Top-level → اسم می‌ذارم روی فایل واقعی**  
**Service-level → با آن اسم فایل را می‌گیرم و داخل کانتینر در `target` قرار می‌دهم.**

---
### اینم یه رخ از کلید کانفیگ در سطح بالا و سطح سرویس
```
services:
  app:
    configs:
      - source: nginx-config
        target: /etc/nginx/nginx.conf

configs:
  nginx-config:
    file: ./nginx.conf
```
