## FROM instruction
---
### در این فایل به این میپردازیم که دستورالعمل FROM  چیست و معمولا در کدام خط میاید و چه کاربردی دارد و چند مدل دارد؟

---
#### قبل از اینکه بخوایم بریم سراغه خوده دستورالعمل FROM این رو باید بفهمید که ایمیج پایه چیه:
## ا-Base Image چیست؟

ا-**Base Image یک Image آماده و اولیه است که Docker برای ساخت Image جدید از روی آن شروع می‌کند.**

یعنی ما به جای اینکه یک محیط کامل را از صفر بسازیم، یک پایه آماده انتخاب می‌کنیم و برنامه خودمان را روی آن اضافه می‌کنیم میتونیم این کارو هم نکنیم که ارگومان به دستورالعمل FROM scratch میدیم معمولا این کارو نمیکنیم ولی همیشه باید FROM بزاریم در خط اول حتی اگر scratch(خالی باشه).

مثال:

```
FROM node:20
```

اینجا:

- `node:20` → Base Image است.
- ا-Docker ابتدا محیط Node.js نسخه 20 را می‌گیرد.
- بعد دستورهای بعدی Dockerfile (مثل COPY و RUN) روی آن اجرا می‌شوند.

روند:

```###
Base Image
     ↓
اضافه کردن کد و تنظیمات با Dockerfile
     ↓
New Image
     ↓
Container
```

چند نمونه Base Image:

```
FROM ubuntu:24.04
```

پایه لینوکسی Ubuntu

```
FROM python:3.12
```

پایه آماده Python

```
FROM nginx:alpine
```

پایه آماده Nginx با حجم کمتر

به زبان ساده:

ا-**Base Image مثل یک قالب آماده است؛ Dockerfile با استفاده از آن یک Image مخصوص برنامه تو می‌سازد.**

---

### حالا دستورالعمل  FROM چیه :
- دستورالعمل FROM مشخص میکند که ما چه image base داشته باشیم چون گفتیم برایه درست کردن داکر فایل باید حتما یه FROM بزاریم حتی اگر خالی است scratch بزاریم

---

### چند مدل ما میتونیم base image  با دستورالعمل FROM انتخاب کنیم:

 برای انتخاب Base Image دو حالت اصلی داریم:

### 1) استفاده از یک Image آماده با Tag (نسخه)

ساختار:

```
FROM image:tag
```

مثال:

```
FROM ubuntu:24.04
```

یا:

```
FROM node:20
```

اینجا Docker یک محیط آماده دارد و ما از همان به عنوان پایه استفاده می‌کنیم.

---

### 2) استفاده از `scratch`

ساختار:

```
FROM scratch
```

اینجا `scratch` یعنی:

«هیچ Base Image آماده‌ای نمی‌خواهم؛ از یک محیط کاملاً خالی شروع کن.»

یعنی:

- سیستم‌عامل ندارد
- shell ندارد
- ابزارهای لینوکس ندارد

معمولاً برای برنامه‌هایی استفاده می‌شود که خودشان به صورت یک فایل اجرایی مستقل (مثل بعضی برنامه‌های Go) ساخته شده‌اند.

---

پس خلاصه:

```
FROM ubuntu:24.04  ✅
```

یعنی:

> از یک Base Image آماده شروع کن.

یا:

```
FROM scratch  ✅
```

یعنی:

> از یک پایه کاملاً خالی شروع کن.

فقط یک نکته: در حالت اول هم در واقع `ubuntu:24.04` یا `node:20` یک **Image پایه** است؛ `scratch` هم از دید Docker یک Base Image ویژه و خالی محسوب می‌شود.

---
### در حالت ۱ که ما برایه from  یه ارگومان میزاریم که scratch نباشه داکر اون رو از کجا میاره
، در حالت معمول وقتی در `FROM` یک Image مشخص می‌کنی، Docker آن Image را از **Docker Hub** دریافت می‌کند (Pull می‌کند).

مثلاً:

```
FROM node:20
```

وقتی این دستور را اجرا می‌کنی:

```
docker build -t my-app .
```

ا-Docker بررسی می‌کند:

1. آیا Image به نام `node:20` روی سیستم من وجود دارد؟
    - اگر **وجود داشته باشد** → از همان استفاده می‌کند.
    - اگر **وجود نداشته باشد** → آن را از Registry دانلود می‌کند.

به صورت پیش‌فرض Registry معمولاً:

```
Docker Hub
```

است.

روند:

```
Dockerfile
    |
    | FROM node:20
    ↓
Docker Engine
    |
    | pull
    ↓
Docker Hub
    |
    ↓
node:20 Image
    |
    ↓
ساخت Image جدید تو
```

البته Docker فقط محدود به Docker Hub نیست. می‌تواند از Registryهای دیگر هم Image بگیرد، مثلاً:

```
FROM ghcr.io/company/app:1.0
```

یا:

```
FROM private-registry.com/my-image:v1
```

ولی وقتی فقط می‌نویسی:

```
FROM ubuntu:24.04
```

ا-Docker معمولاً دنبال این می‌گردد:

```
docker.io/library/ubuntu:24.04
```

یعنی Ubuntu رسمی روی Docker Hub.
