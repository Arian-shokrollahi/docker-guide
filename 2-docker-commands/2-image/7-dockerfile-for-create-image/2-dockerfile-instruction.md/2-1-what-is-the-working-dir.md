##  برایه فهمیدن بهتر دستورالعمل WORKDIR مهم اینه که شما این مفهوم رو بفهمید که مسیر کاری  working directory چیست:
---
خیلی ساده:

**مسیر کاری یعنی پوشه‌ای که Docker فعلاً داخل آن قرار دارد و دستورهای بعدی را آنجا اجرا می‌کند.**

مثل کامپیوتر خودت:

وقتی ترمینال را باز می‌کنی ممکن است اینجا باشی:

```
/home/user
```

اگر بزنی:

```
pwd
```

به تو می‌گوید مسیر کاری فعلی کجاست.

حالا اگر بروی:

```
cd projects/app
```

مسیر کاری می‌شود:

```
/home/user/projects/app
```

---

در Docker هم همین مفهوم وجود دارد.

مثلاً:

```
FROM node:20

WORKDIR /app
```

ما خودمان انتخاب کردیم که مسیر کاری داخل Container باشد:

```
/app
```

یعنی Docker می‌گوید:

«باشه، از اینجا به بعد کارها را داخل `/app` انجام می‌دهم.»

---

### از کجا بفهمیم چه مسیری انتخاب کنیم؟

معمولاً **خود ما انتخاب می‌کنیم**. قانون خاصی ندارد.

مثلاً این‌ها رایج هستند:

```
/app
/usr/src/app
/var/www/html
```

برای برنامه‌ها معمولاً:

```
WORKDIR /app
```

خیلی رایج است.

---

### چرا انتخاب می‌کنیم؟

فرض کن پروژه تو روی کامپیوترت این است:

```
my-project
│
├── server.js
└── package.json
```

وقتی می‌خواهی وارد Image کنی:

```
COPY . .
```

Docker باید بداند فایل‌ها را کجا قرار دهد.

اگر بگویی:

```
WORKDIR /app
```

نتیجه:

```
Container

/app
│
├── server.js
└── package.json
```

---

پس خلاصه:

- **مسیر کاری = پوشه‌ای که دستورات Dockerfile داخل آن اجرا می‌شوند.**
- **ما خودمان انتخابش می‌کنیم.**
- معمولاً برای برنامه‌ها یک پوشه مثل `/app` می‌سازیم.
- مثل `cd` است، ولی برای کل فرآیند ساخت Image تنظیم می‌شود.
