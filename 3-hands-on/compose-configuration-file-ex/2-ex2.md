# Scenario 03 — Nginx + Flask + PostgreSQL

هدف این سناریو ساخت یک معماری سه‌لایه با Docker Compose است.

معماری:

```
User
  ↓
Nginx
  ↓
Flask Backend
  ↓
PostgreSQLا-
```

## Services

- ا-`nginx`
  - از image رسمی `nginx:alpine`
  - ورودی اصلی کاربر
  - پورت `8080:80`
  - درخواست‌ها را به backend می‌فرستد
  - فقط روی `frontend-network`

- ا-`backend`
  - با Dockerfile ساخته می‌شود
  - ا-Flask application
  - با Environment Variable به دیتابیس وصل می‌شود
  - روی هر دو شبکه قرار دارد:
    - ا-`frontend-network`
    - ا-`backend-network`

- ا-`database`
  - از image رسمی `postgres:16`
  - فقط روی `backend-network`
  - دارای `healthcheck`
  - دارای Named Volume برای نگهداری دائمی اطلاعات

## Network Design

Nginx فقط به Backend دسترسی دارد.

Backend به Nginx و Database دسترسی دارد.

Database مستقیماً از Nginx قابل دسترسی نیست.

## Storage

برای PostgreSQL از Named Volume استفاده می‌شود:

ا-`postgres-data`

تا اطلاعات با حذف container از بین نرود.

## نکات اصلی

- ا-Nginx از طریق Service Name به `backend:5000` وصل می‌شود.
- ا-Backend از طریق `DB_HOST=database` به PostgreSQL وصل می‌شود.
- ا-Backend فقط بعد از Healthy شدن Database اجرا می‌شود.
- فقط Nginx به Host publish می‌شود.
- Backend و Database فقط داخل Docker Network در دسترس هستند.
- درون این سناریو با  nginx & flask & postgresql
- هدف پروژه : یه وب‌اپ ساده داریم که کاربر از طریق Nginx وارد میشه، Nginx درخواست رو به Flask می‌فرسته، و Flask به PostgreSQL وصل میشه.

### قسمت دوم بریم تو backend
- ۱- محتوایه app.py چی باشه
```python
import os
import psycopg2
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    conn = psycopg2.connect(
        host=os.getenv("DB_HOST"),
        database=os.getenv("DB_NAME"),
        user=os.getenv("DB_USER"),
        password=os.getenv("DB_PASSWORD")
    )

    cur = conn.cursor()
    cur.execute("SELECT version();")
    db_version = cur.fetchone()[0]

    cur.close()
    conn.close()

    return f"Backend is working and connected to PostgreSQL!<br>{db_version}"

app.run(host="0.0.0.0", port=5000)

```
- قسمت ۲- بک اند فایل نیازمندی هاش چی باشه  requirements.txt (در این قسمت نیاز به vpn) باید در قسمتی که docker compose up میزنید vpn داشته باشید چون قراره درون داکر فایل بنویسیم که این ها رو به عنوان نیازمندی دانلود کند و به مشکل میخوریم چون سایتی که اینارو از میخواد جمع اوری کند فیلتره 
```requirements.txt
flask
psycopg2-binary
```

- قسمت ۳-قسمتی که ما باید docekr file بنویسیم
```
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]
```
- توضیح داکر فایل که نوشتیم که چیکارمیکند
- ۱-ایمیجه پایه ما python:3.12-slim
- ۲-مسیر کاری ما app/
- ۳- ما فایل وابستگی هارو کپی میکنیم در مسیر کاری app/
- ۴- بعد دستورالعمل RUN رو میاریم که در هنگام ساخته ایمیج بیاد اون وابستگی هارو دانلود کند به همراه فلگ nocachedir که سنگین نشه خیلی
- ۵-کپی کردن فایل برنامه در مسیر کاری app.py
- ۶- اینم دقت کنید
ا-`EXPOSE` فقط پورت داخلی کانتینر رو مستند می‌کنه، مثلاً:

```
EXPOSE 5000
```

یعنی برنامه داخل کانتینر روی `5000` کار می‌کنه، ولی این به‌تنهایی پورت رو روی Host باز نمی‌کنه.

برای باز کردن روی Host باید در Compose بنویسی:

```
ports:
  - "5000:5000"
```

خلاصه:

```
ports:
  "HOST:CONTAINER"

EXPOSE:
  فقط پورت داخل container
```
- ۷- قسمت هفتم داکر فایل هم مربوط به اون دستوری است که باید در هنگام ران کانتینر اجرا شه

### قسمت سوم nginx
- در قسمت nginx هم که برایه front میشه یه فایل داریم به اسمه default.conf که این فایله رو این محتوا رو درونش قراره میدیم
```
server {
    listen 80;

    location / {
        proxy_pass http://backend:5000;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## و حالا هم بریم سراغه اصل داستان قسمت compose.yaml که در این فایل تنظیمات composefile رو میدیم
```compose.yaml
services:
  nginx:
    image: nginx:alpine
    container_name: web-nginx

    ports:
      - "8080:80"

    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro

    depends_on:
      - backend

    networks:
      - frontend-network

    restart: unless-stopped


  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile

    image: web-backend:v1
    container_name: web-backend

    environment:
      DB_HOST: database
      DB_NAME: appdb
      DB_USER: appuser
      DB_PASSWORD: apppassword

    depends_on:
      database:
        condition: service_healthy

    networks:
      - frontend-network
      - backend-network

    restart: unless-stopped


  database:
    image: postgres:16
    container_name: web-database

    environment:
      POSTGRES_DB: appdb
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: apppassword

    volumes:
      - postgres-data:/var/lib/postgresql/data

    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U appuser -d appdb"]
      interval: 5s
      timeout: 5s
      retries: 5

    networks:
      - backend-network

    restart: unless-stopped


volumes:
  postgres-data:


networks:
  frontend-network:

  backend-network:
```
