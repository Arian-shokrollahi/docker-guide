### سناریو چیست
# Scenario 01 — Simple Flask App with Docker

## Goal

یک برنامه ساده Flask را از صفر Dockerize کنیم و با Docker Compose بالا بیاوریم.

## Project Structure

```
simple-app/
├── app.py
├── requirements.txt
├── Dockerfile
├── .dockerignore
└── compose.yaml
```

## Application

برنامه باید روی پورت `5000` اجرا شود و وقتی آدرس زیر باز می‌شود:

```
http://localhost:5000
```

این خروجی را برگرداند:

```
Hello from Docker
```

## Requirements

- از image زیر به عنوان base image استفاده شود:
    

```
python:3.12-slim
```

- مسیر کاری داخل container برابر باشد با:
    

```
/app
```

- فایل `requirements.txt` داخل image کپی شود.
    
- dependencyها با `pip` نصب شوند.
    
- فایل `app.py` داخل image کپی شود.
    
- پورت `5000` در Dockerfile مشخص شود.
    
- برنامه با دستور زیر اجرا شود:
    

```
python app.py
```

- اجرای پروژه از طریق Docker Compose انجام شود.
    
- پورت `5000` سیستم به پورت `5000` container متصل شود.
    
- نام container برابر باشد با:
    

```
simple-python-app
```

- restart policy برابر باشد با:
    

```
unless-stopped
```

- image توسط Compose و از روی Dockerfile ساخته شود.
    

## Dockerfile

```
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]
```

نکته:

در exec form مربوط به `CMD` و `ENTRYPOINT` باید از `double quote` استفاده شود:

```
CMD ["python", "app.py"]
```

و این حالت اشتباه است:

```
CMD ['python', 'app.py']
```

چون syntax این بخش بر اساس JSON است و JSON برای string فقط `double quote` را قبول می‌کند.

## Compose File

```
services:
  backend:
    build: .
    image: simple-python-app:v1
    container_name: simple-python-app

    ports:
      - "5000:5000"

    restart: unless-stopped
```

## Important Notes

`build: .`

یعنی image از Dockerfile موجود در build context ساخته شود.

```
build: .
   ↓
Dockerfile
   ↓
Image
```

`image: simple-python-app:v1`

یعنی image ساخته‌شده این name و tag را داشته باشد.

```
simple-python-app:v1
```

`container_name`

نام container را مشخص می‌کند:

```
simple-python-app
```

## Run

```
docker compose up -d --build
```

`--build`

یعنی قبل از اجرای container، image را build یا rebuild کن.

`-d`

یعنی containerها در background اجرا شوند.

## Verification

بررسی container:

```
docker ps
```

بررسی log:

```
docker logs simple-python-app
```

تست برنامه:

```
curl localhost:5000
```

Expected output:

```
Hello from Docker
```

    ↓

    ↓

- 3-نوشتن داکر فایل که میخوایم از ایمیج درست کنیم
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt . 
RUN Pip install -r requirements.txt
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]
```
توضیح داکر فایلی که نوشتیم
- ۱-اول base imagesh رو انتخاب کردیم
- ۲-مسیر کاری که بره تو این مسیر کاری اگر بود میره تو نبود میسازه بعد میره توش
- ۳-کپی کردن فایل requirements.txt درون همین مسیر کاری
- ۴- نصب نیازمندی ها که درون فایل requirements.txt اسمشون هست
- ۵-COPY کردن برنامه ساده به مسیر کاری app/
-  ۶-و انتخاب اینکه کانتینر رویه چه پورتی گوش بده
- ۷-اون دستوری که هنگاهم اجرا کانتینر اجرا شه حتما از دابل کوت استفاده کن نه سینگل کوت چون فرم آرایه‌ای `CMD` و `ENTRYPOINT` در Dockerfile باید با **JSON syntax** نوشته بشه، و در JSON برای string فقط **double quote** معتبره.
- ۴- بریم سراغه نوشتن compose file
```composefile
services:
  backend:
    build:
      context: .
      dockerfile: Dockerfile

    image: simple-python-app:v1

    container_name: simple-python-app

    ports:
      - "5000:5000"

    restart: unless-stopped
```
- بریم سراغه تحلیل این compose file
- ۱-اول top level key سرویس هارو گذاشتیم که بتونیم زیرش سرویس هارو تعریف کنیم
- ۲-بعد اومدیم سرویسمون رو تعریف کردم
- ۳- حالا چون داکر فایل رو خودمون ساختیم و خواستیم که ایمیج از رویه داکر فایلی که خودمون ساختیم ساخته شه اینجا از service level key build برایه اینکه بگیم میخوایم ایمیج رو خودمون درست کنیم
- حالا اگر بخوایم ساده بگیم میگیم  . : build ولی اینجا خواستیم از اون مدل سخته بریم   مدل سخته باید 
- ۳-۱ context تعریف کنیم یعنی مسیری که رویه هاست از رویه اون قراره بیلد شه اون ایمیج و اون مسیری که بهش دسترسی میتونه داشه باشه به فایل هاش برایه ساخت ایمیج
- ۴-حالا اگر یه نکته برایه ایمیج
- اگر داکر فایل پیدا شد و ساخته شد --> اسمه اون ایمیج میشه این ارگومان کلید ایمیج
- اگر نتونست داکر فایل رو پیدا کند میره از لوکالت نگاه میکند که ایا این ایمیج را داری داشتی بر میداره
- اگر در لوکالت هم نبود از زیجستری مثل داکر هاب میگیره اون ایمیج رو 
- ۵- انتخاب اسمه کانتینر 
- ۶-پورت هاست و کانتینر
- ۷- تایین سیاست ریستارت میگه خودت ریستارتش کن اگر داون شد ولی اگر خودم استاپش کردم نکن

---
۱۰۰٪ لازم نیست `--build` بزنی.

اگر داخل Compose داشته باشی:

```
services:
  backend:
    build: .
```

دو حالت داری:

```
docker compose up -d
```

اگر image از قبل وجود نداشته باشه، Compose خودش build می‌کنه.

ولی اگر image قبلاً ساخته شده باشه و تو Dockerfile یا سورسِ داخل build context تغییر داده باشی، ممکنه همون image قبلی رو استفاده کنه.
اینجاست که می‌زنی:

```
docker compose up -d --build
```

یعنی:

> حتی اگر image قبلی وجود داره، دوباره buildش کن.
